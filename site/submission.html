Implementation report

Executive summary

This project delivers an offline educational network-policy demonstration and a Cisco router/switch build kit. Four address zones protect the intended IT/OT boundary. Policy decisions, PAT mappings and simplified reply matching are implemented and tested. The attached Word report serves as a design source, not evidence that this implementation ran in Cisco Packet Tracer.

Workflow delivered

Open dashboard.html locally or serve web/index.html with Python. Use Live lab for custom traffic, Validation & evidence for the 20-check suite and JSON export, and Report coverage for the requirement audit. No additional Mac software is required for the browser workflow.

Policy decisions

Corporate and Admin may initiate HTTPS and approved DNS. The jump host 192.168.30.10 may initiate SSH to internal systems and RDP to SCADA 192.168.20.10. Corporate initiations to OT/Admin, OT Internet access, unsolicited Internet traffic, and routed Telnet are denied. Lab-only ping to 198.51.100.10 is a documented diagnostic exception. Corporate/Admin have PAT; OT is intentionally excluded.

Verification

Twenty browser checks passed, including scenario decisions, PAT uniqueness, matching replies and a wrong-source denial. Browser automation also verified presets, input errors, export, reset and responsive layout. Sixteen Python test methods passed. The ACL subset evaluator checked 5,334 Corporate boundary cases and 253 Admin source cases. The underlying IOS command parser, device forwarding, and actual TLS/SSH/RDP were not executed.

Stateful comparison

The browser and Python models match reverse flow tuples to simulated sessions. They do not validate TCP sequence numbers or implement FIN/RST teardown or idle expiration. The Cisco configuration uses stateless established checks, which accept ACK/RST flags even without a session table. The static ACL test demonstrates this weaker guarantee.

Read-only reporting demonstration

A separate Python standard-library SQLite demo passed 13 reporting checks: the dedicated-host policy tuple, allowed reads, rejected writes/schema changes/overrides and unchanged data. SQLite mode=ro, query_only and a restricted authorizer enforce read-only access on this connection. The assumed reporting host is 192.168.10.60 and the proposed service is 192.168.20.10 TCP 8443. The original strict-deny dashboard does not enable this exception. No HTTPS reporting listener, real cross-VLAN flow or industrial database synchronization is claimed. Local administrators can still open a separate writable connection.

Report corrections

Do not claim that segmentation eliminates ransomware or that NAT completely obscures topology. This is not an air gap. Gateway filters do not inspect same-VLAN flows. Say traffic was dropped rather than connection refused unless a reject was observed. Do not reuse the source report's claimed 100% Cisco compliance as evidence for this implementation.

Completion status

The no-install browser demonstration and supporting materials are complete. The original Packet Tracer execution requirement is not complete. No .pkt topology, Cisco packet captures or real application handshakes are claimed. Production controls, including industrial DPI, endpoint hardening, USB restrictions and hardware data diodes, remain recommendations.

SLIDE 1

Firewall & NAT Security Lab

Speaker notes

This demonstration implements a four-zone policy model for a manufacturing scenario. It runs offline in a browser. Cisco configuration files accompany the model, but I do not claim they have been executed in Packet Tracer.

SLIDE 2

Threat model

Why a flat IT/OT network is risky

  • Compromised corporate hosts can attempt lateral access to OT
  • Telnet exposes credentials in cleartext
  • Unrestricted outbound flows can enable exfiltration
  • Permitted HTTPS still needs endpoint and application controls
Speaker notes

A flat architecture makes it easier for a corporate compromise to reach critical systems. Segmentation adds checkpoints. Blocking Telnet and unauthorized outbound ports reduces exposure, but allowed HTTPS can still carry harmful traffic.

SLIDE 3

Four security zones

VLANs and routed security boundaries

  • Internet: gateway 203.0.113.2; lab web 198.51.100.10
  • Corporate VLAN 10: 192.168.10.0/24
  • Factory OT VLAN 20: 192.168.20.0/24
  • Admin VLAN 30: 192.168.30.0/24; jump host .10
Speaker notes

The gateway separates Corporate, Factory OT, Administration and the simulated Internet. Corporate initiations to OT and Admin are denied. Hosts within a VLAN bypass gateway filtering, so this is not complete host isolation or a physical air gap.

SLIDE 4

Firewall and PAT

Explicit permits, followed by default deny

  • Corporate/Admin: TCP 443 and DNS to 8.8.8.8
  • Jump host only: internal SSH and SCADA TCP 3389
  • OT: no initiated cross-zone traffic and no PAT
  • Corporate/Admin share public address through PAT
  • Browser replies match tuples; Cisco ACLs are stateless
Speaker notes

Default deny drops routed flows unless a rule permits them. PAT maps allowed outbound flows to one public address with distinct ports. It does not guarantee topology secrecy. Cisco established ACL rules inspect ACK or RST flags rather than tracking sessions.

SLIDE 5

Verification results

Measured checks, with evidence boundaries

  • 20 browser checks passed; desktop/mobile controls verified
  • 16 Python test methods passed
  • 5,334 Corporate boundary cases and 253 admin-source cases checked
  • PAT reuse, port uniqueness, allowed replies and denied pivots verified
  • No real TLS/SSH/RDP or Packet Tracer traffic was tested
Speaker notes

I can show the browser validation suite, PAT table, decision log, matching replies and rejected wrong-source replies. Automated tests also evaluate the limited syntax used by our Cisco ACLs. These are model and static analysis results, not observed IOS counters or encrypted application handshakes.

SLIDE 6

Limits and recommendations

What remains outside this implementation

  • Local read-only SQLite demo verified; network service remains unrun
  • Full TCP state, expiration and industrial DPI are not implemented
  • Physical USB threats and same-VLAN access remain
  • Production: endpoint hardening, industrial NGFW and data diodes
  • Packet Tracer is optional for this demo but required for original Cisco validation
Speaker notes

A separate real SQLite demonstration now verifies read-only telemetry queries and rejected writes. A narrow reporting exception is modeled for Corporate host 192.168.10.60 to OT service 192.168.20.10 on TCP 8443. This is an explicit design assumption, not a running network service. Industrial inspection and hardware one-way gateways are future controls. The original Cisco execution requirement remains unfulfilled.
